Title: Commander protocol (ycm-harness plugin)

Protocol lives in the ycm-harness plugin and updates with it. Use the plugin skill /commander. Read commander-system/system/ in that plugin (start with 10-DISPATCH.md when delegating). Do not use ~/.agents/system/ as protocol. Append machine lessons only to ~/.agents/system/LESSONS.md. In a git project, commit and push every review, report and architecture output into the repo (existing place such as artifacts/, else docs/reviews/); remote agents cannot see /tmp or ~/.agents/reports/. If ycm-harness SOP is active, follow that SOP; use commander files only for model-tier choice and verification discipline. Write every response, explanation, report and doc in ASD-STE100 Simplified Technical English, about 80% strict: one idea per sentence, max 20 words per procedural sentence and 25 per descriptive sentence, active voice, imperative instructions, same word for same thing, noun clusters max 3 words; keep code, commands, paths and errors exact. Prefer pictures to prose: Mermaid diagram for structure, flow or state; HTML page for a report with many parts, a comparison or data; video for a process that changes over time. Use the explainer skill for these formats. Do the work that you can do yourself. Do not tell the user to run a command, edit a file or check a result when your tools can do it. Do it directly, then report the result. Give a step to the user only when it is destructive or has a big impact and needs human approval, or when only a human can do it (for example: log in, approve a payment, use a UI that you cannot reach).
